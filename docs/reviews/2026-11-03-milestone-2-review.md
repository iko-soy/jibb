## Verdict

**Milestone 2 is not done by its own "Done when" list.** Every check passes, the 14 `jibb` blocks of the doc check as written, and nothing wrong that the core probes tried was accepted. But the checker that a build will run, the full module checker, reports almost every error in the spec as "module definitions need unsupported inference: <path>: ++ name", with no line, column or excerpt. And the island, page and store checks are fitted to the examples' exact shapes, so small valid edits are rejected, often with a wrong error. `docs/status.md` still says "In progress", which matches; its rewrite as a capability table (`e97aebe`) landed while this review ran.

## What works

- The 14 doc blocks check with exact, closed types, including the todo island, the cart store and basket, the theme, the three pages and the imports example, and the `cmd`/`sub` block as prelude source.
- About 64 of 90 valid edits to those modules still check: reordering and renaming, unused helpers, consistent field swaps, an `init` written as a cast, a sixth message, helpers in `view`, two islands on a page.
- Overlapping union cases, a repeated field in a Jibb record, and derived-name clashes get good errors from the full checker, with both sites and excerpts. The unresolved-tag error of the Grammar's buttons example is exact, and moves with the code when the block is reordered.
- None of the wrong programs probed in this version was accepted, apart from the two in M9.

## Early results from the areas still running

These come from probes the inference reviewer had run when this version was written. They have not been through that reviewer's own write-up or a second reviewer, so treat them as leads:

- Every wrong program in about 40 soundness probes was rejected, except the two in M9 and a gate passed where `*` is expected (A23, known).
- Common valid code is rejected as "unsupported": a sum with `roll`, a pair of mutually recursive top-level gates, list reverse, factorial, a recursive count, a pattern binding the rest of a list, wing access on a union or list, and patterns over atoms with number or string literals.
- `~[1 "a"]` checks as `(list @t)`: a bare decimal takes the aura `@t`. The spec allows that today; syntax-review proposal S4 would forbid it.
