# The compiler

A map of `jibb-dev/lib/jibb.hoon`: the layout pass, parser, module graph and type checker. The library's design notes explain the syntax rules and the shared inference core. Milestone 2's general full checker has replaced the specialized recovery paths, and all report expectations use the full-check pipeline. [Status](status.md) records final acceptance validation, validated capabilities, and remaining gaps.

The plan's Compiler architecture section gives the whole pipeline. Here it is shortened, with the milestone that builds each step; milestone 1 built the first line:

```
/ui source
  → layout pass → parser → a syntax tree per module            milestone 1
  → module graph: imports resolved, Hoon types read from Clay   milestone 2
  → type checker, one module at a time, in dependency order     milestone 2
  → core language                                               milestone 3
      → Nock                                                    milestone 3
      → JavaScript                                              milestone 6
```

The common checker retains `proj` actions alongside each checked definition. Each action keeps the original expression, selected field axes and resolved source and result types. Local generic definitions quantify their own proof variables when they generalize; final module substitutions cannot capture those variables. The enclosing definition owns each action once, including actions in mutually recursive local gates. The focused projection and compatibility suites passed 38 arms under eval and on the fake ship. Lowering and execution remain milestone 3 work.

## Core language and lowering

`jibb-core.hoon` defines the independent 15-node Core tree, its canonical S-expression reader and printer, and the strict Hoon reference interpreter. `jibb-nock.hoon` emits Nock for that tree with Hoon-shaped gates and explicit native registries. The two executors compare canonical nouns and crash/no-crash outcomes; functions are applied to noun samples rather than compared as backend closures.

The successful full check can retain a `checked-module` containing resolved references, final occurrence types, field axes, dependency SCCs, match evidence, projections, derived plans, and authenticated native identities. `check-jibb-file-for-lowering` and its prepared-prelude variant return that artifact and its enriched dependency cache without changing the existing full-report result. Failed or provisional checks publish no artifact.

`jibb-lower.hoon` consumes only those checked artifacts: it does not parse, infer, or repeat coverage. It lowers modules, links reachable definitions per entry, and expands derived API and store calls. Runtime module identifiers omit the display-leading slash, while Core module names retain their logical paths. Unsupported projection reordering and unavailable type-directed printers fail closed.

## Static builds

`jibb-build.hoon` is the facade the host calls through each desk's own `%ca`-built copy. `+module-outline` gives one module's direct Jibb, `/sur` and mark imports, the `/sur` names it uses, as `item.todo`, and whether it may be a page. `+check-module` checks one module against the interfaces and artifacts of its already-checked dependencies; `+theme-look` checks the theme and makes the desk's stylesheet, giving its language too; `+render-checked` links a static page, its theme and the renderer from artifacts, executes them as Nock, checks the page's links and images, and serializes the HTML without checking any module again; `+prepare-page` and `+page-request` do the same for a page with data, at build time and per request; and `+error-page` renders Jibb's error page. `+build-static` composes the same arms for one page and is what the build suites call. The host calls each entry point with `+slam`, typing every argument with the desk's own copy of its mold, so a desk whose compiler takes a different layout is a type error at the call rather than a misread noun.

The host reads a `/sur` file's declared arms, and also each name the module uses that the file does not declare, so a misspelled mold gets the importer's "not declared" diagnostic with the file it was looked for in. When a `/sur` file builds on its own against `zuse`, with no Ford runes, the reader is given the type of that rebuild rather than Clay's: Clay's built core carries debug spots that make its generic `|$` arms, as `|$  [key value]  (map key value)`, compare unequal with the importer's own rebuild. A file with `/-` or `/+` imports still gets Clay's type, so its generic molds are still reported unsupported. The host and the importer rebuild with `+mint` rather than `+ride`, which would print three progress lines in the dojo for every file.

The host, `jibb/app/jibb.hoon`, watches each published desk's commits and builds the new revision as a list of steps: scan the sources and their imports, prepare the prelude, read each imported `/sur` file and mark, check each module in dependency order, render each page, and publish. It runs one compiler step per Behn wake, so no single event checks a whole desk, and the last completed build keeps serving meanwhile. Every result is cached under a hash of its inputs: a module's own source, the sources of everything it imports, the reader results its closure uses, the prelude, and the desk's `/lib` and collection reader. A commit therefore checks again only the modules it changed and their dependents. The planning arms are pure and live in `jibb-host.hoon`.

### Static files, the stylesheet and links

Files under `/ui/static/` keep their bytes through jibb-dev's marks, which store each as `octs`. A file's application path joins the Clay path's last two segments, so `/ui/static/img/logo/png` is `%/static/img/logo.png`, and it is served at the desk's base path, `/static/`, the first 40 bits of its bytes' `+sham` as `@uv`, and the rest of its path, as `/apps/my-app/static/0v1.7rq2a/img/logo.png`. The host puts each file in Eyre's cache with `%set-response`, public and marked immutable, so Eyre answers for it without an Arvo event. A file the new build no longer uses, because it changed or went, stays a day for pages already open, and a Behn timer removes it. Suspending a desk removes all of its files, and `-jibb!clear`, which pokes the host, removes every desk's; the next build of each desk puts its files back. A request that reaches the host for a file under `/static/` or `/~jibb/` is a 404 for anyone, since Eyre answers for every file it holds; no page is routed under `/ui/static/`.

`+check-theme` checks the theme before anything renders with it: spaces and `wide` are CSS lengths, and `wide` is not a percentage, since a media query cannot use one; tones are hex colours; `lang` is a language tag; every tone has 4.5:1 contrast with its `background`, as do the dark tones with theirs, by WCAG's relative luminance; and the font names a static font file. `+theme-stylesheet` then makes the one stylesheet a desk's pages share, served like a static file at `/~jibb/s/<hash>.css`: the tokens as custom properties, dark tones under `prefers-color-scheme`, the font's `@font-face`, the heading and role sizes of the Typography decision, and one atomic class per layout attribute value, as `j-pad-s2` or `j-tone-accent`. The renderer emits class names, with `chars` and `fill` the only inline styles, and the browser's decoder makes the same classes. Pages also carry a Content-Security-Policy that allows scripts only from the ship.

`+render-checked` checks the links and images of the page it rendered before serializing them. A `link` to a static file needs the file, and one to a page needs a route that matches, where a `_` folder or file matches one segment and `__` the rest. An `image` names a static image whose width and height the build can read from PNG, GIF, JPEG, WebP or SVG bytes, and draws it with them. A failure is the page's error, as `missing static asset: /static/img/logo.png` or `link to a missing page: %/blg`. `link-unsafe` and `image-unsafe` are drawn only for a root-relative path, other than `//` or `/\`, or an `https`, `mailto` or `tel` URL, with no space or control byte, since browsers drop tabs and newlines inside a URL; anything else is drawn as text. The check runs on the rendered tree, so its errors name the path but not a source site; dynamic pages and islands, which render later, will need a static check.

### Pages with data

A page whose `main` is `(page load view)` is prepared when the desk builds: `+prepare-page` links and executes `load` and `view`, the theme and the renderer, and reads `load`'s sample fields from the checked type. The checker has already required, for a page under `/ui`, that the sample has exactly the route's parameters: a `_name` file or folder is a parameter, an atom whose aura a path prints and parses, and a final `__name` the rest of the path, a `path`; a page with none takes `~`, and one whose only parameter is a catch-all takes the path itself. Each request then goes through the desk's `+page-request`. It binds the sample from the address, parsing each parameter by its aura, where `@ta` and `@tas` must be knots and a segment that does not parse is a 404; runs `load`; and renders a `%pure` ask at once. For an agent's ask the host scries `%gx` at the case's path, or its separate `scry=` path, with the `noun` mark, in a thread on `%jibb`: Gall cannot recover from a failed scry, so a path the agent rejects ends the thread rather than the host's event, and is the page's 404. The noun goes to the ask's receiver, then `view`. A crash anywhere is a 500. Failed requests get Jibb's error page, with the theme's language and stylesheet and the message as preformatted text, and nothing about a page with data is cached, in the host or in Eyre.

Routes keep their files' `_` and `__` segments. A literal segment beats a parameter, which beats a catch-all, from the first segment on. Two files that route to the same address, two parameters or two catch-alls at one level, and a catch-all beside its folder's index are each file's error.

A derived request's receiver checks each fact before its typed reply or fold sees it, as a Hoon clam would: the first against full state, each later one against the diff its mark names, which the fold receives tagged with that mark. A map or set's order is not checked, and a type the checker cannot reproduce in Core yet, such as a recursive mold, fails closed when the request is lowered.

### Islands

An island module's `main` is `(program init update view subs)` and a store's `(store init update)`. Lowering pairs each `island` call's program with the path of the module whose `main` it is, which the checker's import evidence gives, so the island element carries `[[module program] data]`: a program's value cannot name its module, since its gates capture their subject. When a page renders, the renderer runs the island's `init` on its data and its `view` on the model in Nock, renders that view with controls allowed, and wraps it in `<div data-jibb-island="HASH">`, followed by `<script type="application/x-jibb-state">` holding the jammed model as `@uw`. Fields are read-only until the browser starts the island. A crash in `init` or that view renders the crash notice in the island's place.

The host compiles each island and store module for the browser after the checks: `+prepare-browser` links the module's `main` and compiles its Core with `jibb-js.hoon`, a port of `js/core/compiler.mjs` that emits the same text for the same Core, as `tests/js-emit` checks. Each module's JavaScript, and the browser library the desk vendors as `/lib/jibb/runtime.js`, become public, immutable files in Eyre's cache at `<base>/~jibb/m/HASH.js` and `<base>/~jibb/r/HASH.js`. A page importing islands or stores gets a client context, the library's URL, the ship, each island module's hash and each store's, and its HTML then carries that configuration with the page's static files as `<script type="application/x-jibb-client">` JSON, and loads the library as a module script. An island or store that fails to compile is the error of each page that imports it.

`tools/bundle-js` bundles `js/browser/entry.mjs` into `/lib/jibb/runtime.js` with esbuild, and the `bundle-js` check fails when that file is stale. In the browser, `boot` registers each store once for the page, then for each island imports its module, cues the server's model, starts the island from it, and replaces the server's view with its own; `Effects` connects it to one Eyre noun channel per page, opened after its first request. A generated receiver takes its last state as a unit, `~` before the first fact, and an agent's receiver takes the fact's mark too. An island that crashes keeps its model and shows the crash notice; one whose module fails to load, or whose first view crashes, keeps the server's view under the notice. A page under a catch-all route is an app: its configuration names the section the route covers, the route's literal prefix, as `/app` for `/ui/app/__rest`; links and `go` commands within it change the address with `pushState` rather than loading a page, focus moves to the first heading, and `%url` gives the path within the section, as the page's `load` was given it. Elsewhere `%url` gives the application path.

### Tests

A module under `/ui/tests` is a library whose `test-…` arms are each one test. `+run-tests` links each arm as an entry and runs it in Nock: `%.y` passes, and `%.n`, a crash, or an arm whose type is not `?` fails with the reason. The host keeps each desk's last completed build, unsaved, as it keeps its caches, and answers `/x/test/<desk>` with every test module's outcomes, a module that failed to check giving its error. `-jibb!test %desk`, the thread `jibb/ted/test.hoon`, waits for the host's build of the desk's current revision, prints a line a test, and gives the outcomes.

`+test-programs` gives the same arms as the JavaScript the browser would run and the Nock the ship would, the Nock naming each native by a placeholder, `[[0 0] 0 %jibb-native name]`, rather than carrying the ship's gates, which would bring the compiler with them. The host answers `/x/test-programs/<desk>` with them, and `tools/check-node-tests` runs them in Node with `tools/node-tests.mjs`: the JavaScript with the native registry, and the Nock with `js/nock/interpreter.mjs` and the JavaScript natives in the placeholders' places. Both must agree, with each other and with `-jibb!test`.

### Clay reads

Gall cannot catch a failed scry, even under `+mule`: it fails the whole event. So the host scries a file only after a `%u` scry says it exists, and builds a Hoon file through `%ca` only after a `%warp` `%sing %a` request has answered that it builds; Clay answers a failed build with an empty writ. An imported `/sur` file or mark that does not build is the error of the modules that import it, and a `/-` or `/%` name with no file is reported with its importer. Names resolve to files as Clay's `fit-path` does, dashes before slashes. The prelude is composed from the desk's own `/lib/jibb/prelude-groups.txt`, as the eval tools read it.

## JavaScript backend

`js/core/` implements the milestone 6 track that can proceed without surface lowering: a hand-written-Core reader, Jibb literal decoder, noun runtime, and Core-to-JavaScript code generator. `linkCore` resolves module-qualified definition identities, prunes by entry reachability, orders dependency SCCs, rejects recursive non-gates, and emits one linked Core program per definition entry or whole-module value. `compileLinkedCore` combines that program with the generator. Native evidence is preserved from lowered `(native …)` nodes rather than inferred from definition spelling; the host compiles checked islands with the Hoon port of this generator, `jibb-js.hoon`. `compileCore` produces an ES module whose `evaluate` function receives an explicit runtime and native registry. Native names must be declared at compilation and validated again at instantiation; spelling alone does not authenticate a prelude definition. Atoms are BigInts and cells two-element arrays. Each operation checks its operands one level deep, so every cell a program makes, through `cons` or `edit`, is well formed throughout, and an operation costs only what it reads; `same` checks whole nouns, cycles and functions included. Cords' decodings are cached, a bounded number of them, since a view decodes the same text on every render. A module-level gate or recursive arm is wrapped in `memo`, which remembers its last four samples and products, since one render may call a gate from several places, matching a cell by its two parts, and a lambda inside a gate whose free names are all module-level is made once, in a slot `$hN`; so a view whose list and row gate did not change returns the same `each` element as before. The browser keeps each element's vnode on the element, and passes over a vnode it already shows. A program with a trace is compiled without `memo`, so every trace prints. `js/core/node.mjs` evaluates generated modules for Node tests; it is not the browser runtime. `tools/test-js` covers all Core nodes, strictness and crashes, arbitrary-precision values, closures and mutual recursion, higher-order natives, and malformed reader inputs. `js/test/fixtures/hand-written.json` is a language-neutral seed corpus of source text, required test natives, and canonical noun/crash outcomes for the later Hoon differential harness. `tools/test-js-differential` runs the shared corpus through both JavaScript and the Hoon Core interpreter in `master`, translating the JavaScript AST directly to Hoon `expr`; `--core-lib PATH` selects another interpreter. All 11 shared outcomes matched. Separate probes lowered checked Jibb literal and authenticated-`add` modules and executed them through `linkCore`, both returning 42.

### Browser DOM and island loop

`js/browser/` decodes authenticated sealed element nodes into renderer-independent virtual nodes, creates and patches DOM, and reconciles keyed `each` children and table rows in occurrence order. Compatible nodes retain identity, focus, selection, and caret; control properties are rewritten only when they differ. Button, toggle, field, form, and composition events dispatch synchronously. `startIsland` initializes or resumes a jammed model, mounts the first view, queues reentrant messages, patches before ordered commands, resynchronizes controls on unchanged models, and retains the previous model after update/view failures. Commands require an explicit transport. `Channel` implements Eyre noun channels with `application/x-urb-jam` request batches, sent one at a time in order, and streamed SSE decoding of Eyre's noun events, whose acks carry Gall's `(unit tang)` and whose facts name their desk, cumulative acknowledgement batching, resume IDs, fresh-UID reconnect on 404, and pagehide deletion. `Effects` installs command dispatch and subscription diffs: agent watches retain fold state, reseed after kicks, acknowledge after handling, unsubscribe on removal, and reject refused watches. Poke replies, one-shot and interval timers, `now`, `who`, and `go` are supported. `StoreRegistry` shares per-page stores, defers initial full-state watches, notifies every island after successful pokes, preserves state on update crashes, and returns deferred error text. `UrlRuntime` delivers initial and subsequent paths, handles `go` with `pushState`/`popstate`, and focuses the first heading after navigation.

The host hashes each island or store's generated module independently of the page and its initial data. Pages therefore share immutable module files, while `boot` evaluates each module once per page and creates that page's own stores and island models. The boot regression uses two documents with the same imported module namespace to check this separation; the host and browser fixtures use the same rows island on `/bench` and `/bench-small`, with 500 and 3 rows respectively.

Both JavaScript emitters analyze linked Core for fixed view templates: `js/core/view-template.mjs` and `jibb-js-template.hoon` follow lexical bindings, known cells, projections and ordinary gate applications to authenticated `raw-seal` calls. They recognize no source constructor names. Fixed `row`, `column`, `wrap`, `stack` and `el` support constant attribute nouns; `para`, known heading levels and text also retain their static structure. A descriptor fixes the DOM structure; noun axes select changing text or complete elements. Printable ASCII constants are static, while other text uses the ordinary decoder. Unknown shapes, controls, keyed collections, dynamic attributes and unknown child-list tails become whole-element holes within a fixed layout. A wholly dynamic root uses ordinary rendering. Analysis is bounded to 2,000 Core nodes and 128 descriptor nodes, with independent 128-node constant-attribute and 128-cell child-list checks. Exhausting any bound declines the whole plan. Abstract projections and used axes must fit JavaScript's safe integers. Larger projections remain ordinary Core, including the JavaScript runtime's existing rejection of axes outside that range.

Descriptors use strings for static text, nonnegative indices for text holes and `-1-index` for element holes; both hole kinds share one axis list. Fixed nodes are `[tag, attrs, children]`. A numeric `attrs` selects the constant attribute noun from the first returned view; in this form `tag` names the layout and its DOM tag is `div`. Ordinary attribute decoding preserves duplicate-family handling and validation order at mount.

The emitters call `viewTemplate` after memoization and before closed-lambda hoisting. The generic Core runtime makes this an identity operation: its callers may supply arbitrary JavaScript gates that mutate cells. Only browser boot, which loads checked host modules, supplies `compiledViewTemplate` to attach the descriptor and optional direct hole evaluator. The browser also requires the canonical frozen `loweredNatives` table: a custom native can mutate a known cell, and a mutable registry can replace the seal implementation. First mount evaluates the ordinary view, decodes its constant attributes and creates static DOM. A changed view identity uses ordinary rendering.

`js/core/direct-template.mjs` and `jibb-js-direct.hoon` specialize eligible updates into one ordered computation returning a private JavaScript array of hole values. The public view still returns its original sealed noun. Known lexical gates producing fixed view structure are inlined; opaque bound calls keep their original gate and memo cache. Their source-proven result shape remains available to later layout analysis, including constant attributes made by helpers. Cells and seals stay virtual until an opaque operation, captured value or element hole needs an ordinary value. A whole pure wrapper may use its original gate when materialized, retaining that cache too. Strict discarded work, selected branches and traces remain in order. The exported shallow `checkValue` retains removed cells' validation and exact operation labels. Captured lexical references, including the current parameter of an optimized tail loop, stay bound to their original scope. Escaping callbacks capture materialized values once. Closed callbacks reuse the ordinary emitter's lazy function slot, so list memoization also retains the callback used at first mount. Matching requires a unique syntax site with the same captured references; ambiguity keeps ordinary view evaluation. A separate 2,000-step budget bounds syntax visits, sample-shape conversion, projections and materializations, including conditional-branch probes. A probe identifies values that predate a conditional but need materialization within it; those values are emitted in the outer scope, so shared cells and callbacks retain their ordinary identity without exporting branch-local bindings. Unknown captures, local recursive expressions and exhaustion omit the direct evaluator and retain ordinary view evaluation with the existing DOM template.

Updates compute and decode every hole before changing any DOM; element holes use the ordinary decoder with the page's paths and the existing keyed DOM patcher. The owning vnode's child and remembered DOM node follow replacements, preserving control resets and later ordinary rendering. `tests/view-template` covers checked sources with text, constant attributes, controls and keyed-list boundaries; emitter fixtures compare both generators. Runtime tests cover provenance, decoding failures, paths, independent instances, control focus and caret, keyed reordering and changed view identities. `js/bench/template-allocations.mjs` compares separately instantiated ordinary and optimized views, counting generated `cons` cells, `edit` path cells and canonical seal wrappers. These counts exclude native internals, JavaScript hole arrays and closures, DOM allocations and heap bytes. Browser checks guard the timer, todo and 500-row islands against revisiting static attributes or replacing retained DOM.

### Nock comparison and tail calls

`js/nock/` contains an independent Core-to-Nock emitter and iterative Nock 0–11 interpreter used for correctness tests and backend comparison. Native adapters and Hoon-shaped gate nouns share the sample-at-axis-6 ABI. `tools/bench-js` checks expected nouns before measuring source emission and execution separately. Direct self-tail-calls in generated JavaScript become loops, including through `if`, `let`, and `rec` bodies, with fresh parameter bindings per iteration to preserve captured closures. Trace-wrapped recursion retains ordinary call semantics. The 2026-11-08 comparison selected generated JavaScript for the browser backend; see [optimizations.md](optimizations.md#measured-javascript-and-nock-comparison) for measurements and remaining performance limits.

### Native runtime

The browser passes each compiled module the fixed, frozen `loweredNatives` table and the twelve runtime primitives used by both Core emitters, including `viewTemplate` and `checkValue`. Node's test registry additionally registers the other native identities; that mutable registration machinery is not bundled for the browser. Hashing, calendar conversion, ship-name permutation rounds, and noun validation have shared implementations. `tools/bundle-js` uses pinned esbuild and Terser, with standard compression and identifier mangling; it enables neither unsafe transformations nor property mangling. `--check` checks the generated file and enforces the shared library's limit of fewer than 20,000 bytes under `gzip -9n`.

`js/natives/` implements arithmetic and comparison, strict UTF-8 byte/codepoint conversion, cord joining, aura formatting, list and unit gates, persistent Hoon treaps with `mug`/`gor`/`mor`, `jam`/`cue`, exact `@uw`, and deep noun validation. `createNativeRegistry` installs only explicitly requested identities with immutable function properties. The checked raw mappings cover arithmetic, comparison, text, formatting, calendar pack/unpack, aura-directed parsing, bit complement, sealing, and map get/put; deliberately omitted collection-door APIs are not manufactured from names. Composed Unicode convenience functions remain separate from the exact `trip`/`tuba`/`crip`/`tufa` primitive steps. Native and registry tests include arbitrary-precision values, higher-order callbacks, malformed inputs, persistent map/set versions, independent Hoon vectors, and canonical codec round trips.

## Constraints

- **One core, no Ford runes.** `urbit eval` runs the library as `=>  <this file>  <expression>`, and a ship builds it as `/lib/jibb.hoon`. So it can't import with `/-` or `/+`, and under `urbit eval` it can't scry. Anything from Clay, such as an imported module's text or a `/sur` file's type, is best passed in by the caller, which keeps every stage testable under eval.
- **The standard library is the subject.** Under `urbit eval`, as on a ship, the library is built against `..zuse`: `hoon.hoon`, lull and zuse. It reads literals with Hoon's own parser, `nuck:so`. Hoon's type engine, `ut`, is there for milestone 2, and under eval `ride` compiles Hoon source, such as a `/sur` file without Ford runes, into a type, which tests can use in place of Clay's builds.
- **The spec wins.** Where the file and the spec disagree, the spec is right, and the file's notes quote its words for each rule they implement. The repository spec records the decision to drop `$?`.

## API

From the header of the file:

| Arm | Takes | Gives |
| --- | --- | --- |
| `+layout` | `[file=path src=@t]` | `(list token)`: never fails; an error is the last token |
| `+layout-error` | `[file=path toks=(list token)]` | `(unit error)`: the error token's error, if any |
| `+parse` | `[file=path src=@t]` | `(each module error)` |
| `+parse-tokens` | `[file=path toks=(list token)]` | `(each module error)` |
| `+golden` | `[file=path src=@t]` | `[tokens=@t tree=@t]`: both stages printed, or the rendered error |
| `+golden-types` | `[file=path src=@t]` | The full checker’s definition types and module kind, or its diagnostic with excerpts |
| `+golden-types-imports` | `[file=path src=@t externals=iexternals]` | The full result with caller-supplied Hoon mold results |
| `+show-tokens` | `(list token)` | `@t` |
| `+show-module` | `module` | `@t` |
| `+show-error` | `[src=@t error]` | `@t` |

A file is a Clay path whose last segment is the extension, as `/ui/basket/jibb`. The `golden-types-with-*` entry points add prepared prelude, mark and module inputs to the same full checker. An unsupported construct remains an error; reporting does not publish a partial interface as a checked module. The renderer preserves nominal identities and all generic arguments. It first uses visible mold aliases; when a value exposes a type from a transitive Jibb import, it adds a report-only import such as `/= types-1 /ui/base` and prints `(phantom.types-1 @t)`. These aliases do not change source scope or the checked interface. They avoid existing names, and distinct origin modules keep distinct aliases. A nominal identity with no available checked origin still reports its limitation at the definition’s source site. Diagnostics retain the known structure of incomplete types: an unresolved tag prints as a type variable with its literal constraint, rather than hiding the surrounding record or pretending the union is fixed. Constructor mismatches use the known union’s payload type; calls retain the successful argument-prefix substitution so both concrete conflicting auras are shown. At the module boundary, a failed branch join recovers the original arm expression to keep the decimal/aura suggestion and both source excerpts. The old `golden-types-in-context*` partial-report implementations and their unused printers have been deleted. All report tests use the full checker; remaining old golden expectations are still being reviewed, and unsupported valid programs remain failing regressions.

Inference diagnostics can carry sites from more than one source file. For a missing case in an imported Jibb union, the checker reports the union declaration from its checked source and the tag from the current module. It uses the checked import graph and the exact sources of that import's closure to establish the origin, including through transitive imports; if that source is unavailable or ambiguous, it does not invent an excerpt. Local diagnostics keep their existing spans and excerpts.

## Where things are

The core is split into chapters, `+|  %name`, in this order:

| Chapter | Holds |
| --- | --- |
| `%positions` | `loc`, `span` and `error` |
| `%tokens` | `token`, `lexeme`, `glyph` and `lit`: what the layout pass emits |
| `%tree` | The syntax tree: `module`, `import`, `def`, `expr`, `piece`, `qseg`, `item`, `edit`, `arm`, `sample`, `field`, `pattern`, `shape` and `pseg` |
| `%api` | The arms above that aren't printers |
| `%lexer` | The layout pass's door, `+lexer`, and its helpers |
| `%printers` | `+show-tokens`, `+show-module`, `+show-error` |
| `%parser-helpers` | Error building (`+fail`, `+fail-in`, `+fail-space`, `+fail-line`, `+moved`, …) and the `+then` combinator |
| `%parser` | The parser's door, `+parser`: one arm per EBNF rule, as `+read-module`, `+read-expr`, `+read-mold` |
| `%span-check` | `+check-spans`, which `+golden` runs on every tree, and `+check-spans-test` |

## Type checking

`infer-jibb-file-detailed` resolves imports, checks mold declarations and infers the module through `icore-check`. The public text-result adapter and every `golden-types*` reporter read that same result. A failed definition prevents publication of the interface. There is no second resolver that accepts a source-shaped recovery case after the common checker declines it.

The dependency graph uses a lexical traversal: samples, patterns and local definitions bind names, while references to outer values remain edges. Two depth-first passes find strongly connected components. Dependencies are inferred before their users. A recursive group shares monomorphic placeholders while its bodies are checked and generalizes only after the group succeeds. A non-gate dependency cycle reports the actual declaration and reference chain. A failed group rolls back its substitutions; independent later definitions can still resolve earlier constraints, without making the failed module publishable.

Type variables carry binding levels and restrictions for atoms, numeric literals and gate freedom. Unification checks occurrence before binding a variable and lowers reachable levels when a value captures an outer variable. Generalization uses these levels and the pending constraints; it preserves captured variables and independently instantiates quantified variables, including restrictions nested in lists, records and recursive types. Written capitals have lexical scope and cannot be forced to a concrete type or merged with another distinct written capital. A type hole must be resolved by its own definition before generalization; later uses cannot repair it.

Local mold capitals have lexical scope through local recursive mold graphs, including nested graphs. Their capture relationships survive deferred generalization, while independent mold parameters still generalize and unbound or out-of-scope captures are rejected.

One queue carries unresolved literal, constructor, cell, call, cast, field, change, match, face, printable-aura and attribute constraints. Its wake index tracks the variables reachable from each edge, including aliases and structural bindings, so unrelated substitutions need not retry every edge. The full solver remains a reference implementation for the indexed solver. Pending tag variables remain monomorphic until module context determines their union. Finalization reports a remaining edge at its own source instead of publishing an open type. The queue retains argument positions, called-gate types, written capitals and definition ownership as compound constraints are decomposed.

Expected subscription event context reaches delayed expressions through direct lists and lists transformed by `identity` or `flop`. Valid streams infer their event type through the ordinary constraints; a wrong event produces a type error rather than merely leaving inference unresolved.

A capital meeting a faced position binds the type beneath that face. Structural joins retain a face once the position has one and reject incompatible face names. Sample binder faces and value faces therefore do not require a source-layout exception for a directly named gate: aliases and inferred callbacks use the same constraints. Module-kind template matching preserves raw `%slot` markers until gate-sample pairing, so written binders are not mistaken for value faces. `unface` explicitly removes value faces. A `proj` keeps checked field axes as an elaboration attached to its owning definition; generalized local proof variables remain independent of later module substitutions.

A monomorphic gate result can retain a module-owned structural root until later uses supply its faces. That root is allocated before scheme-local renaming and only when its product has no variables that will generalize and no private occurrence evidence. Tag-constrained variables remain module-owned. Independent polymorphic calls keep distinct product variables; collection, union and recursive arguments receive their own structural face joins.

Recursive Jibb and imported molds use one nominal graph representation, `%mrec`, with checked source identities and explicit arguments. Traversals use graph nodes and guarded unfolding rather than separate example-specific recursive wrappers. A structurally guarded recursive mold may have no finite inhabitants; certification preserves its identity without asserting that it contains a value. Saved schemes retain their reachable roots and restrictions. They instantiate with fresh variables and do not expose private mold names or change a nominal origin to make a fit succeed.

Private occurrence evidence supports proofs such as “this broad noun contains no gate.” It is attached to the value that established it. When values join, structural evidence is intersected field by field; evidence available in only one alternative cannot justify the result. Face-only queue updates preserve the target's evidence or its absence. Binding a capital beneath a face does not copy that occurrence's proof into every use of the capital. This keeps equality, collection-key and island-data checks sound under aliases, casts and repeated generic parameters.

Watch checking follows actual request occurrences through local and embedded islands, including generic embedding helpers and islands discarded by surrounding data flow. A data-only absence proof does not manufacture request evidence, and an unproved subscription reports its own watch site.

The checked `each` and `table` signatures constrain keys to contain no gates, including gates nested inside a key. The constraint survives aliases and generic wrappers; an element's message may still contain a gate.

The match checker specializes a pattern matrix over noun constants and cells. Loobeans, lists, units and named recursive unions supply their possible constructors. Usefulness identifies an unreachable arm; exhaustiveness produces a missing-case witness. Patterns retain source spans and the refined types of their binders, including a final binder that captures a cell tail. The matrix is reusable by milestone 3's lowering pass. The old per-case, collection and closed-cell branch recovery paths have been deleted. The integration passed 65 suite arms and six exact diagnostic goldens under eval and on the fake ship, including local body contexts and recursive result faces.

`main` is inferred with the other definitions. The kind check then examines its checked type and applies the kind's additional constraints, including gate-free data and models and evidence for each watched request. Kind checks are type-directed, and watchability follows actual request occurrences and their checked provenance. Lowering, runtime behavior and route checking are later milestones.

## Imports and prelude

The host supplies imported module sources and Hoon reader results. Under eval, tests can build Hoon fixture types with `ride`; on a ship, the desk check uses types built through Clay. `jibb-import.hoon` reads those Hoon types, and the Jibb checker preserves their auras, record faces, union cases and recursive identities. An unsupported or invalid imported type is reported where it is used, with source evidence when available. Checked import graphs bind interfaces to the sources, declarations and dependencies that established their evidence; a changed source cannot reuse a stale proof. A certificate covers exactly its own transitive import closure: the paths and versions of those sources, and the reader results it was checked with, compared for the same `/sur` modules and marks. A source outside the closure cannot reach the check, so a host may keep an interface across commits that leave its closure unchanged; a supplied interface that no longer agrees is an error, not a silent recheck. `jibb-cache-scope` checks both directions, including the diagnostic excerpt from a reused import.

Source-aware mark reading authenticates origin evidence against a unique declaration rebuilt from the supplied source and matched to the mark's faced dependency. The checker reads origin only from a unique direct result for that mark; another mark's declaration cannot supply it. The selected declaration and the raw dependency must have the same canonical `read-mold` representation, which avoids Ford-versus-eval raw-type representation differences without accepting equal-shaped decoys. Missing, stale, wrong-path or ambiguous origin metadata produces no origin rather than a guessed site. Source evidence does not change the imported semantic body or hide a semantic import error.

The prelude is Jibb source, prepared through the checker. Its private internal module can use a small validated primitive interface. Public helpers and module constructors are ordinary values with checked signatures; their names do not bypass unification. Standard list and unit recognition is tied to their validated source templates. The [prelude inventory](prelude-inventory.md) records available names, their source groups and deliberate omissions.

The element type uses a compiler-owned private seal. The source-backed internal prelude defines the unsealed element node and the public prelude builds nodes through its ordinary typed constructors before sealing them. The seal's checked private origin and type arguments survive imports and instantiation; the display name is not its identity. Ordinary modules cannot import the sealing primitive, inspect an element's representation or cast a raw noun into an element. This is private implementation metadata for element opacity, not a public type operator. In particular, an island constructor still checks its program and initial data through their source-defined types before sealing the result.

## Diagnostics

An inference diagnostic is a message and a list of source sites. The common checker retains the owning definition and the original argument, declaration or constraint spans until rendering. Errors are selected in dependency order. An earlier independent unresolved tag can precede a later failure; a tag whose context comes from the failing definition does not hide that definition's actual error.

Conflicting types, fields, capitals and bindings show the relevant sites with excerpts and carets. Imported union and scope diagnostics use the checked origin source. A genuine implementation limit still rejects the program and names the unresolved construct and its location. The public reporter never substitutes a partial list of successful definitions for a failed module.


## The tree

Every node is `[%tag at=span …]`, so `+span-of` finds its span in one place; the few that aren't say so in the `%tree` chapter. The kinds of node:

- **Module**: imports (`%sur` for `/-`, `%mark` for `/%`, `%jibb` for `/=`), then definitions (`%mold` for `+$`, `%value` for `++`).
- **Expressions** (`expr`): `%lit`, `%str`, `%path`, `%qath`, `%wing`, `%change`, `%pair`, `%unit`, `%group`, `%list`, `%tuple`, `%gate-wide`, `%ctor`, `%call`, `%gate`, `%cast`, `%trace`, `%branch`, `%crash`, and `%body` for an indented body, with its local definitions if it has any.
- **Molds as written** (`shape`): `%aura`, `%hole`, `%noun`, `%void`, `%flag`, `%const`, `%ref`, `%tvar`, `%path`, `%apply`, `%cell`, `%union`, `%fn`, `%generic`. A `%hole` retains the span of `_`; an inferred typed path segment retains that span separately from its enclosing segment. A `%union` spans its first through last case and has no lead token; a single case is its own mold. `%generic` spans from the `|$` after a `+$` name through its body.
- **Samples, fields and patterns**: a sample is `%bind`, `%face`, `%pun`, `%cell` or `%bare`, since a bare name binds anywhere in a sample; a pattern is `%lit`, `%str`, `%any`, `%bind` or `%cell`.
- **Literals** (`lit`) keep the form they matched, their aura and value, and their text as written, which the printers show.

The parser accepts type holes and retains each hole's span. The checker diagnoses an unresolved hole before its definition can generalize. A separate syntax-tree pass reports repeated record fields at both written sites, including in unused definitions; nested and separate records have independent scopes.

The tree keeps everything the checker needs to report an error at the code as written: open and closed brackets give the same node, but every node keeps its span.

## Positions and errors

- A span runs from a node's first character to just past its last. A node ends where its last token ends, never at a layout token, and holds its children's spans in order. `+check-spans` tests both rules on every tree the golden tests print.
- An error is `[file=path line=@ud col=@ud msg=tape]`: a start, no end yet. Milestone 2's type errors need more, since the plan asks that "each error names both conflicting sites, with excerpts". Spans keep their ends for that.
- Every error points at the first character where the text stops being the start of any valid module (note 2.0). The layout pass never fails: it ends its tokens with an error token, and the parser reports whichever error comes first, its own or that one.
- The parser's messages read "expected <what>, found <token>", with an optional "; <hint>". The layout pass's state the rule broken, as "a tab: Jibb uses spaces only" or "`|%` is left out: modules are records". None ends with a period, and all start lowercase unless they open with a name, as "Jibb writes no @c literals". `+show-error` prints `<file>:<line>:<col>: <message>`, the line, and a caret under the column.

## Printed formats

Note 4 has examples of each.

- **Tokens**: one per line, `<line>:<col>`, then `tight` if the token follows the previous one on its line with no space between, then its kind and text.
- **Trees**: S-expressions, `(kind line:col fields kids)`, with each node's start; a node whose kids are all leaves prints on one line. Past 64 levels the indent stops growing, so the printed tree stays linear in the text's size.
- **Errors**: as above. Control characters print as spaces in the excerpt, so the caret stays under its column.

## Tests

`tools/golden` runs `+golden` under `urbit eval` on every case and compares `tokens.txt` and `tree.txt`; opted-in cases also compare `+golden-types` with `types.txt`. `tools/ship gen-tests` writes a `-test` arm per case that does the same on the ship. The type output comes from the full checker: checked definition types and module kind, or its diagnostic with source excerpts. Rendering selects visible mold aliases from the module, its direct imports and the prepared prelude. A separate print view reconstructs alias arguments without changing the checked scheme, including aliases that reverse, repeat or fix parameters. A nongeneric specialization prints without spurious type arguments; an inaccessible nominal type is reported rather than losing its identity.
